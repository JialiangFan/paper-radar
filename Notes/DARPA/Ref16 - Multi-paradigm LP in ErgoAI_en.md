# Multi-paradigm Logic Programming in the ErgoAI System

## Research Problem
How to unify multiple knowledge representation paradigms (F-logic, defeasible reasoning, reactive updates) in a single system with Python/LLM integration for real-world deployable reasoning.

## Topic
Multi-paradigm Knowledge Representation and Reasoning

## Background
ErgoAI (abbreviated Ergo) is an open-source knowledge representation and reasoning (KRR) system developed by Coherent Knowledge, designed for scalable reasoning over hybrid knowledge — both structured knowledge and knowledge derived from external sources such as vector embeddings — in dynamically changing environments. Ergo is the successor to and replacement for the Flora-2 system. Its language is grounded in HiLog (higher-order syntax) and Frame Logic (F-logic, supporting objects, types, and inheritance), set within a strong dynamic module system. Unlike ASP solvers and description logic provers, Ergo is based on the Well-Founded Semantics (WFS), which provides low-order polynomial data complexity, sound evaluation of non-ground negation, and eliminates the need for grounding.

## Limitations & Research Problem
- **Limitation:** Existing logic programming systems — Prolog, Datalog, and ASP — each exhibit significant limitations in expressiveness, scalability, or reasoning paradigm. Prolog lacks default support for well-founded negation; ASP requires grounding and incurs higher data complexity; Datalog does not support unrestricted logical terms as data structures. No single existing KRR framework coherently unifies object-oriented knowledge modeling, defeasible reasoning, transactional updates, and higher-order syntax within a sound semantic foundation.
- **Research Problem:** How to design a multi-paradigm logic programming system that unifies F-logic (with non-monotonic inheritance), HiLog (higher-order syntax), defeasible reasoning (via argumentation theories), transactional updates, and tight integration with external languages (Python, Prolog, C) — all under Well-Founded Semantics — to support scalable KRR in dynamically changing environments.

## Contributions
- Presents the ErgoAI system, which unifies F-logic, HiLog, defeasible reasoning, and transactional updates within a coherent Well-Founded Semantics framework, achieving a high degree of multi-paradigm integration both syntactically and semantically
- Introduces a powerful dynamic module system that supports runtime module creation, dynamic loading of rules and data, cross-module invocation, and encapsulation for modular knowledge management
- Develops Generalized Courteous Logic Programming (GCLP) as the default argumentation theory, supporting defeasible inheritance, explicit negation, rule tagging, and conflict resolution via \opposes, \overrides, and \cancel predicates; additionally provides multiple pluggable argumentation theories (including RefuteCLP) that can be active simultaneously in different modules
- Implements a transactional updates framework based on transaction logic, ensuring semantic consistency of each update in dynamic environments, coupled with reactive tabling and integrity constraints for automatic inference updating and alerting
- Achieves tight integration with Python via the Janus interface, enabling direct use of external knowledge sources such as vector embeddings from Language Models (e.g., Phi-3, Universal Sentence Encoder)

## Methodology
- **Language Foundation:** F-logic serves as the basis for base statements (frame formulas, class membership, subclass formulas), supporting plain and inheritable data frames, direct inheritance, overriding, and monotonic type inheritance. HiLog provides higher-order syntax where functors and predicates can be arbitrary (non-ground) terms; HiLog terms are translated to Prolog via the tr_H transformation for resolution, yielding first-order semantics with higher-order syntax.
- **Module System:** All HiLog and F-logic statements are translated with respect to a specific module; the module symbol appears only in the outermost functor (e.g., applyMod/n). Modules can be dynamically created, loaded, and encapsulated. Cross-module calls use the @OtherMod syntax, and different argumentation theories can be active in different modules simultaneously.
- **Defeasible Reasoning:** Built on the GCLP argumentation theory, each defeasible rule is annotated with an optional tag descriptor. Three user-facing predicates — \opposes (declares conflicts), \overrides (specifies priorities), and \cancel (disables rules) — implement defeat, rebuttal, and refutation mechanisms. When two opposing facts are neither overridden nor canceled, GCLP sets both to false (unlike WFSX which would assign undefined), making it more suitable for paraconsistent default reasoning.
- **Dynamic KRR:** All rules and facts are treated as dynamic information (insertable, deletable, enableable, disableable). Transaction logic ensures transactional semantic consistency of updates. Reactive tabling automatically propagates updated inferences when data changes. Integrity constraints trigger alerts or actions when updated inferences satisfy specified conditions.
- **External Integration:** The Janus interface provides tight connectivity with Python, enabling calls to Python APIs (e.g., TensorFlow Hub) to load Language Models and obtain vector embeddings as Ergo object attributes. Prolog, Python, and C are treated as special modules for seamless interoperation. Ergo programs compile to XSB Prolog, leveraging XSB's tabled evaluation for efficient incremental reasoning.
