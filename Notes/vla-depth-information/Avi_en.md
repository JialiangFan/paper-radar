# Avi: A 3D Vision-Language Action Model Architecture generating Action from Volumetric Inference

## Topic
3D point cloud VLA model

## Background
Vision-Language-Action (VLA) models have gained traction, but the vast majority operate solely on 2D image input and are trained end-to-end to directly predict robot-specific action tokens. Avi takes a different route: it operates natively on 3D point clouds, building on an existing 3D Multi-modal LLM (ShapeLLM-Omni, a Qwen-2.5 VL backbone plus a 3D VQ-VAE), and performs volumetric inference. It reframes the decision-making process as language-conditioned 3D geometric reasoning, then derives actions through classical geometric transformations (ICP + inverse kinematics).

## Limitations & Research Problem
- **Limitation:** Existing VLAs rely on 2D perception, making reasoning about depth, object geometry, and fine-grained spatial relations indirect and error-prone. They also directly generate robot-specific action tokens, tying the policy to a particular morphology and scene setup, which hurts generality and reproducibility.
- **Problem:** Can we build a VLA that operates natively on 3D representations (point clouds), shifting action generation from "language-to-action" to "language-to-geometry" — predicting the desired post-condition state (point cloud) of the manipulated object(s) — so that behaviors are robust to occlusions, camera-pose changes, and viewpoint shifts, and remain morphology-agnostic?

## Contributions
- **AVI (Action from Volumetric Inference):** an architecture that uses a 3D MLLM to infer actions through volumetric reasoning — predicting a goal (delta) point cloud and then computing actions via geometric optimization — rather than directly generating action tokens. The key shift is that the architecture does NOT train on previous action tokens, only on previous depth maps / point clouds, moving the focus from language-to-action to language-to-geometry for richer spatial grounding.
- **Location Quantization for 3D MLLMs:** a general technique for discretizing spatial information that lets a pretrained 3D MLLM generalize at the object level rather than only the scene level. Each segmented object's quantized centroid (X/Y/Z, each 256 bins → 768 position tokens) and quantized scale (128 bins → 128 scale tokens) are encoded as new vocabulary tokens (896 added tokens total). This overcomes the bottleneck that ShapeLLM-Omni was trained on single online 3D assets and struggles with multi-object robotic scenes.
- **Preliminary results on LIBERO drawer-closing:** Avi stays robust across scenes (Scene 5 → Scene 10, with a changing object count) and outperforms ResNet-RNN / ResNet-T / ViT-T / Diffusion Policy baselines (0.90 on Scene 10 vs. 0.70 best baseline), demonstrating robustness to domain shift.

## Methodology
- **Overall pipeline (language-to-geometry):** The input is the scene's 3D point cloud (obtained via stereo reconstruction, not 2D images). (1) Segment Anything (SAM) performs 2D segmentation that is geometrically lifted into 3D, partitioning the scene point cloud P into disjoint per-object subsets P_k. (2) Each object undergoes location quantization, yielding a discrete descriptor ℓ_k=(x_k,y_k,z_k,s_k) (quantized centroid + quantized scale) converted into location tokens appended to the object representation. (3) The text instruction T and the geometric modality are mapped by encoders (f_text, f_3D) into a shared latent space Z. (4) The 3D MLLM autoregressively predicts the next/goal 3D volumetric state, which the VQ-VAE decoder reconstructs into a voxel grid and then back into a point cloud.
- **How the 3D representation enters the model:** The core is a frozen 3D VQ-VAE encoder that maps a 64×64×64 voxelized shape into 8192 discrete latent tokens drawn from a learned codebook C. The MLLM (built on Qwen-2.5 7B VL) draws tokens from three vocabularies: the text vocabulary V_text (Qwen-2.5), the pretrained ShapeLLM-Omni 3D codebook V_3D, and the newly added position/scale vocabulary V_loc. The joint distribution is factorized autoregressively as p(z)=∏ p(z_i | z_<i), so the model conditions on past geometry tokens as well as on language instructions and quantized spatial context — i.e., language-to-geometry generation within a single discrete token space.
- **From volumetric inference to action:** Given instruction T and current point cloud P_t, the model predicts a goal point cloud P̂_{t+1} ≈ P_t + ΔP (ΔP is the learned, prompt-conditioned spatial change — the "next-timestamp" prediction shown as green voxels in Fig. 1). Iterative Closest Point (ICP) then solves for the rigid transform (R∈SO(3), t∈ℝ³) minimizing the alignment error min_{R,t} Σ‖R x_i + t − y_i‖² between source and target point clouds. This transform is applied to the end-effector pose (X,Y,Z), and inverse kinematics solves and executes the robot joint actions. Because actions are derived purely from geometry, the policy is morphology-agnostic.
- **Training data and stages:** Fine-tuned on the LIBERO dataset (Robosuite environment, Franka Panda, synchronized RGB-D observations and proprioceptive states), using 50 demonstrations of the drawer-closing task. Hardware is a single NVIDIA A6000 (48GB). Fine-tuning uses LoRA: low-rank adaptation matrices are inserted into the Q/K/V projections of the last K attention layers, sweeping rank r∈{4,8,16,32,64} with LoRA_α=2r; the SAM encoder and VQ-VAE remain frozen throughout, with dropout p=0.05 for regularization in the low-data regime. The 896 new-token embeddings are randomly initialized while the original embeddings are preserved to retain pretrained knowledge. Each example is trained for ~100 epochs.
- **Limitations and future work:** The current design explicitly generates the next point cloud and cannot perform long-horizon high-level planning; the autoregressive transformer plus VQ-VAE tokenization demand high precision (cross-entropy loss occasionally produces out-of-step point clouds, leading ICP to compute incorrect transforms). Future directions include unfreezing the VQ-VAE for richer supervision, introducing a 3D diffusion-policy / diffusion-style loss in place of cross-entropy, and integrating stronger 3D MLLMs (e.g., SpatialVerse).
