# 3D-VLA: A 3D Vision-Language-Action Generative World Model

## Topic
3D generative world model for embodied action

## Background
Most existing vision-language-action (VLA) models operate on 2D inputs and learn a direct perception-to-action mapping, neglecting the dynamics of the 3D physical world and the relations between actions and states. Humans, in contrast, possess world models that let them imagine future states before planning actions. 3D-VLA introduces a family of embodied foundation models that seamlessly link 3D perception, reasoning, and action through a generative world model. It is built on top of a 3D large language model (3D-LLM) and equips embodied agents with human-like 3D understanding and the ability to first imagine a goal, then act.

## Limitations & Research Problem
- **Limitation:** Existing embodied foundation models (e.g., RT-2, PALM-E) learn only a direct perception→action mapping; they cannot imagine future states or simulate world dynamics. Existing embodied datasets are mostly 2D images/videos, lacking depth/3D annotations, 3D bounding boxes, and goal states needed for reasoning and planning in 3D space.
- **Problem:** How to build a human-like world model grounded in 3D representations that can both reason/localize in 3D scenes and imagine multimodal goal states (image/depth/point cloud) to drive action generation — and how to obtain large-scale embodied training data with the required 3D annotations.

## Contributions
- Propose **3D-VLA**, a new family of 3D vision-language-action embodied foundation models that unify 3D perception, reasoning, and action via a generative world model.
- Curate a large-scale **3D Embodied Instruction Tuning Dataset** (~2M 3D-language-action pairs) by extracting and completing 3D information from existing robotics and human-object-interaction datasets, addressing the absence of 3D annotations in current embodied datasets.
- Introduce a set of **interaction tokens** (scene / object / location / action tokens) to better interact with and ground objects in dynamic 3D scenes.
- Pretrain **embodied diffusion models** (RGBD-to-RGBD, point-to-point) for goal image / depth / point cloud generation, and use a **projector** to align their decoders with the LLM embedding space, enabling goal imagination. 3D-VLA outperforms 2D baselines by a large margin across reasoning, multimodal goal generation, and action planning.

## Methodology
- **Backbone (3D scene representation):** Built on 3D-LLM, starting from a pretrained BLIP2-FlanT5_XL VLM. Rather than training a point-cloud network from scratch, it follows 3D-LLM: extract 2D features from **multi-view RGB images** via the pretrained VLM, then lift them into **3D features** (using camera intrinsics/poses to project RGB-D into a 3D point cloud). The 3D features are encoded by a **Q-Former** and fed to the LLM; the Q-Former and the input/output token embeddings are unfrozen during training.
- **How depth/3D enters the model:** On the data side — since >95% of video data lacks 3D info, **ZoeDepth** estimates per-frame depth and **RAFT** optical flow enforces frame-to-frame background depth consistency, so RGB-D can be lifted into a 3D point cloud with camera intrinsics/poses; spaCy parses instruction nouns and **Grounded-SAM** produces 2D masks that, lifted to 3D, yield object **3D bounding boxes (AABB)**; 7-DoF actions come from the source datasets. On the model side — depth/3D enters as "3D features extracted from multi-view images (via Q-Former) + 3D tokens in text (loc/scene/object)." Thus depth is used both to build the 3D scene representation and to generate 3D supervision annotations.
- **Interaction tokens:** `<obj></obj>` mark manipulated/referred objects; `<loc0-255>` (six tokens) represent the AABB of a 3D bounding box; `<scene></scene>` enclose static-scene embeddings to express dynamic scenes; robot actions use discrete tokens `<aloc0-255>`, `<arot0-255>`, `<gripper0/1>` (absolute location/rotation/gripper openness), with actions separated by `<ACT_SEP>`.
- **Generative world model & goal imagination:** Generation ability is injected in two steps. (1) **Pretrain embodied diffusion models**: RGBD→RGBD uses Stable Diffusion V1.4 (concatenating RGB latent and depth latent as the condition); point→point uses **Point-E** (with an added point-cloud condition). They are trained as conditional diffusion that edits the initial state per instruction to generate the final state, yielding decoders that imagine goal image / depth / point cloud. (2) **Bridge LLM and generation (alignment stage)**: introduce special tokens `<image></image>`, `<pcd></pcd>`; between them the LLM generates the instruction-for-execution plus object/location tokens, and a **transformer-based projector** maps the LLM decoder features and embeddings into the diffusion-model space, so goals are generated for whatever modality the instruction specifies. Each diffusion model is fine-tuned with **LoRA**; only the new token embeddings, their output linear layer, and the whole projector are trained, minimizing both the LLM loss and the diffusion denoising loss.
- **Coupling to action:** The imagined goal state (image/point cloud) can be fed back to guide **robot control** — the model first imagines the goal state, then, using the 3D features and localized key objects, outputs 7-DoF action tokens for planning. Because leveraging 3D information enables more accurate localization of key objects and goal imagination, reasoning, localization, and action planning all surpass 2D baselines.
- **Training data & stages:** Three stages — (1) backbone training of the 3D-VLA base on the 3D Embodied Instruction Tuning Dataset (task caption, action prediction, localization, multimodal goal generation, etc.; ~2M pairs); (2) pretraining the embodied diffusion models (RGBD/point cloud); (3) alignment stage (projector + LoRA to attach diffusion to the LLM). Data sources: 12 robot datasets from Open-X Embodiment + depth-rich Dobb-E/RH20T + simulators RLBench/CALVIN + human-object-interaction data (Epic-Kitchens, HOI4D); language annotations built with templates and ChatGPT rewriting. Evaluation spans Embodied/Task/What-if/Dense QA, localization, RGB/point-cloud goal generation, and action planning on RLBench/CALVIN.
